# AI 美食社媒情报 Agent V2｜方案讲解稿

## 一句话定位

我没有重做一套采集器，而是在 SocialReader 的小红书/抖音通用采集底座上增加 `food_v1` 可插拔领域方案，把“收藏内容”转成可回溯、可审核的新品证据、品类知识和推荐理由素材。

## 业务问题

原系统可以按关键词采正文、评论和视频转写，但单关键词、前 N 条与按点赞排序无法证明平台全站热门；通用爆款 Prompt 也无法稳定区分产品新品、帖子新发布与个人第一次体验。更重要的是，生动表达如果没有原句定位和人工审核，很容易变成模型扩写。

## 方案变化

1. 搜索前：用人工词库组成品类、趋势、描述三轴矩阵，模型只能补充候选，用户勾选后才能采集。
2. 搜索后：先保存完整可见候选池，再按同平台、同关键词、同次运行分别计算互动分位；跨平台不相加原始互动量。
3. 详情层：食品属性、新品证据、活人感原句分开抽取，每项都有 `content_id`、公开 `source_url`、`source_type` 和 `evidence_location`。
4. 判断层：模型只负责抽证据；新品、相对热门与活人感阈值由确定性规则判断；人工状态单独保存。
5. 输出层：只有人工通过且规则通过的 evidence_id 才能进入推荐理由。

- 2026-09-04 小红书重新低频采集 3/3 成功；3 条归档链接均保留详情访问需要的 `xsec_token`，2 条视频完成本地 ASR，1 条按“无可识别语音”降级保留正文评论。
- 抖音重新低频采集 2/2 成功，正文、评论和视频转写均可核验；因搜索卡片点赞字段不稳定，保持页面原顺序，没有伪装成点赞排序。
- 当前演示运行只包含 5 篇重新采集的真实内容，不混入旧演示卡或任务书边界夹具；55 条原句证据全部可逐字回溯并保持待人工审核。
- 小红书真实搜索页重新保存 27 条带可访问签名的可见候选，再排序选出 8 条；系统组互动分位中位数为 0.673077，固定随机基线为 0.5，差值 +0.173077。由于只有点赞可读，指标完整度仅 25%，所有候选都不得给出强热门结论。
- 当前库存有 5/24 篇真实待标内容，但人工确认金标准仍为 0/24，因此没有生产准确率。评测程序会强制输出 `production_metrics=null`。

## 必须主动说明的口径

当前“热门”定义为同平台、同关键词、同次候选池中的相对热门，并结合跨来源重复出现形成趋势候选；没有平台全量数据，不能声称还原官方热榜。

新品不是看到“新”字就判断，而是由可识别产品、发布时间和明确上新原句共同决定。抽取负责证据，规则负责标签，人工负责最终金标准。

活人感拆为食品相关性、具体性、感官丰富度、口语自然度、记忆点和推荐可用性六项，并用原句回溯和人工审核控制误判。
